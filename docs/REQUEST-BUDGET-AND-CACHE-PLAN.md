# Request budgets and catalogue cache review

## Implemented in this change

Authenticated account actions: 120 requests/60 seconds per verified user ID. Profile-state POST: a separate 30/60 seconds per verified user ID, shared across that user's sessions. Logout remains available. Existing authentication/password brute-force limits stay in place. The account-session probe retains existing behavior and is not covered by the authenticated action budget.

Public TMDB lookup/detail routes: 600/60 seconds combined per hashed session cookie, or per hashed IP for guests. This is a preliminary load guard, NOT authentication or a verified per-user quota. Cookies can be replaced; an edge WAF rule would be needed to counter broad anonymous abuse. The 600 budget intentionally accommodates today's up-to-500 automatic title lookups. Unrelated API routes, admin import jobs, static assets and direct supplier media are outside these budgets.

429 responses carry `Retry-After`, `retryAfter`, a safe Portuguese error and `Cache-Control: no-store`. Personal-state writes honor cooldown and recover after it; only version conflicts stop further writes until reload. Metadata remains optional, so rate-limited artwork must not prevent playback.

Counters never use D1. Worker deployment config declares three native `ratelimits` bindings (namespace IDs 2201–2203, reserve these for Lux). Native limits are approximate per Cloudflare location, not worldwide billing ceilings. If bindings are absent or fail, a bounded 8192-key per-isolate memory fallback is used. A restart/eviction/distribution across isolates can reset/bypass that fallback. **Pages uses its own deployment settings: changing Worker wrangler.jsonc does not prove these bindings exist on Pages.** This PR does not claim remote configuration was performed.

The limiter does not eliminate D1 session validation reads. It prevents subsequent action reads/writes after authentication. Rejected requests have already reached the Worker and still count as requests. It cannot stop billing before the edge or supplier streaming abuse. No blanket daily user cap was added: request count is a poor proxy for legitimate watch time, and a distributed durable daily counter would add a separate cost.

Player changes are messages/control visibility only. Network errors and startup timeout display “Falha na conexão com o vídeo”; decode and unsupported-format errors remain distinct. A new selection clears the old error. Existing engines, HTTPS preference, source identity, startup timeout and bounded HLS retries remain unchanged. Protected cinema-app baseline updated for these authorized changes only; bridge hashes untouched. Midstream buffering is not falsely declared a permanent failure merely because it is slow.

## Agreed architecture, still pending implementation

1. At 05:00 America/Sao_Paulo (08:00 UTC), build a prepared catalogue snapshot, with resumable bounded batches. Existing 03:00/04:00 jobs and minutely maintenance must be reconciled, not duplicated. This change DOES NOT reschedule jobs or start imports.
2. Separate public editorial data from private account/provider credentials. A shared CDN catalogue contains stable IDs, names, grouping and optional display metadata; never supplier URLs, tokens or credentials. A private M3U/snapshot stays authorized and partitioned by source/account. A single shared catalogue is valid only for users entitled to that same catalogue. Keep playback's original source URL selection untouched.
3. Build the file first; validate counts/structure; publish an immutable content-hash version; update a small manifest last. Include schemaVersion, contentVersion/hash, generatedAt, source identity and counts. Checking a version must not query D1. Unchanged content does not generate a new download merely because a daily timestamp changed.
4. Keep a local IndexedDB copy; show it immediately; check the manifest in the background with short cache/revalidation. CDN must not indefinitely retain an old manifest. Validate new download before atomically activating it; retain old copy on interrupted download, quota failure or corrupt data. Empty or partially imported output must never replace a healthy catalogue.
5. Consider separating series-level browsing metadata from large episode payloads (260k records). Measure compressed transfer, expanded heap and phone storage. Do not eagerly download every image or all season metadata. Local storage can be unavailable/evicted; provide a working fallback and honest state.
6. The current code STILL sends recent progress about every 9 seconds; the 5-minute sync + 10-second local save plan is NOT implemented here. Implement a durable outbox without media URLs, per account AND selected profile. Coalesce repeated progress records; preserve changed favorites/settings immediately; sync only dirty data. Retry network/429/503 with exponential backoff/jitter and Retry-After, retaining unacknowledged data.
7. Flush on player exit and visibilitychange/pagehide, plus every 5 minutes during long viewing. Last-second uploads are best effort, not a guarantee. Persist before sending; remove only the acknowledged revision, so changes made while an upload is in flight survive. Coordinate tabs to avoid redundant uploads.
8. Resolve 409 conflicts explicitly, merging by item and timestamps with deletion markers for favorites; never overwrite another device with a stale full-state snapshot. Prevent cross-account replay after logout/login, clear visible private data and partition any retained pending outbox. Explain temporary cross-device sync delay.
9. Cloudflare payment does not remove the application's internal 5000/day TMDB lookup quota (and separate details quota). Today's frontend caches reduce repeats; first uncached TMDB requests still touch D1. The old draft PR76 remains paused; this change does not merge it. Decide presentation routing separately instead of assuming D1 independence already exists.
10. Initial import/classification still consumes writes and index updates. Steady-state refresh should apply only actual changes, preserve manual edits and avoid writing every row or progress counter on every tick. Add a global import lease/checkpoints and expose actual counts/failures before promising free-tier operation.

## Validation

Unit/integration suite covers independent users/categories, window expiry, native-binding/fallback behavior without D1, hashed metadata identity, route exclusions, safe playback errors, 429 cooldown recovery and existing conflict protection. Full suite result recorded in TAREFAS.csv. Production bindings, authentic playback, multi-device synchronization and CDN publication require separate validation; do not infer them from unit tests or a successful static deployment.
